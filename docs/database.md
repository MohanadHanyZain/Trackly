# TrackPro — Database Design (STEP 3 baseline)

**Date:** 2026-11-16  
**Status:** Draft — Phase 1 core tables only  
**Dialect:** PostgreSQL via Drizzle ORM  
**Migration tool:** Drizzle Kit (`db/migrations/`)

## General rules
- Internal IDs: `uuid` primary keys via `gen_random_uuid()`.
- Human reference numbers: separate columns (tracking numbers, invoice numbers) generated by safe tenant-scoped sequences — never `COUNT(*) + 1`.
- Money: `numeric` (never float/double), stored with currency code (`EGP` default).
- Timestamps: `timestamptz` UTC storage; local display in application layer.
- Tenant isolation: `tenant_id` on every business table; indexes on `(tenant_id, ...)`.
- Soft delete: `deleted_at` nullable timestamp where applicable; financial rows never hard-deleted.
- Audit: `created_at`, `updated_at`, `created_by` on business tables.

## Phase 1 tables (core)

### Tenancy
**tenants**
- `id` uuid PK
- `name` text
- `slug` text UNIQUE
- `domain` text
- `settings` jsonb default '{}'
- `status` text (active/suspended/trial/expired)
- `created_at`, `updated_at`
- Index: `tenants_slug_idx` on slug

**organizations**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `name` text
- `legal_name` text
- `tax_id` text
- `commercial_register` text
- `address` text, `governorate` text, `city` text
- `phone` text, `email` text
- `status` text
- `created_at`, `updated_at`
- Index: `organizations_tenant_id_idx`

**branches**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `organization_id` uuid FK → organizations
- `name` text
- `code` text (unique per tenant)
- `address`, `governorate`, `city`, `phone`, `email`
- `manager_id` uuid FK → users (nullable)
- `working_hours` jsonb
- `status` text
- `created_at`, `updated_at`
- Index: `branches_tenant_id_idx`, unique `(tenant_id, code)`

**hubs**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `name`, `code`, `address`, `phone`
- `status` text
- Index: `hubs_tenant_id_idx`

**departments**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `name`, `code`
- Index: `departments_tenant_id_idx`

**tenant_settings**
- `tenant_id` uuid PK → tenants
- `settings` jsonb default '{}'
- `updated_at`

**tenant_domains**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `domain` text UNIQUE
- `is_primary` boolean default false

**tenant_features**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `feature_key` text
- `enabled` boolean default false
- unique `(tenant_id, feature_key)`

**tenant_sequences**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `entity` text (shipment, invoice, settlement, ...)
- `prefix` text
- `last_value` bigint default 0
- `padding` int default 6
- unique `(tenant_id, entity)`

### Identity & authorization
**Note:** Better Auth manages its own `user`, `session`, `account`, `verification` tables via its Drizzle schema. TrackPro app tables reference `auth_user.id`.

**user_profiles**
- `id` uuid PK
- `auth_user_id` uuid UNIQUE (references Better Auth user)
- `full_name` text
- `avatar_url` text
- `phone` text
- `language` text default 'ar'
- `timezone` text default 'Africa/Cairo'
- `created_at`, `updated_at`

**roles**
- `id` uuid PK
- `tenant_id` uuid FK → tenants (nullable for platform-level roles)
- `key` text (e.g. `company_admin`)
- `name` text
- `description` text
- `is_system` boolean default false
- `created_at`
- unique `(tenant_id, key)`

**permissions**
- `id` uuid PK
- `key` text UNIQUE (e.g. `shipments.create`)
- `description` text
- `module` text

**role_permissions**
- `role_id` uuid FK → roles
- `permission_id` uuid FK → permissions
- PK `(role_id, permission_id)`

**memberships**
- `id` uuid PK
- `user_id` uuid FK → Better Auth user
- `tenant_id` uuid FK → tenants
- `role_id` FK → roles
- `status` text (active/invited/inactive)
- `created_at`
- unique `(user_id, tenant_id)`

**user_branch_access**
- `user_id` uuid FK → user
- `branch_id` uuid FK → branches
- PK `(user_id, branch_id)`

### CRM
**customers**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `type` text (individual/company/merchant)
- `name` text
- `tax_id` text
- `phone` text
- `email` text
- `address`, `governorate`, `city`, `area`
- `credit_limit` numeric default 0
- `balance` numeric default 0
- `status` text
- `created_at`, `updated_at`
- Index: `customers_tenant_id_idx`

**customer_contacts** / **customer_addresses** — 1:N from customers, tenant_id denormalized.

**contracts**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `customer_id` FK → customers
- `starts_at`, `ends_at` timestamptz
- `credit_limit` numeric
- `settlement_terms` text
- `return_terms` text
- `status` text (draft/active/expired/terminated)
- `version` int default 1
- `created_at`, `updated_at`

**contract_versions**
- `id` uuid PK
- `contract_id` FK → contracts
- `snapshot` jsonb
- `effective_from` timestamptz
- `created_at`

**customer_rate_cards**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `customer_id` FK → customers
- `service_type` text
- `governorate` text
- `weight_from_kg` numeric
- `weight_to_kg` numeric
- `price_per_kg` numeric
- `min_charge` numeric
- `cod_fee` numeric
- `effective_from`, `effective_to`

### Shipments
**shipments**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `tracking_number` text UNIQUE (human reference, e.g. TP-2026-000001)
- `customer_id` FK → customers
- `external_order_id` text
- `service_type` text
- `shipment_type` text
- `priority` text
- `status` text
- `origin_branch_id` FK → branches
- `destination_branch_id` FK → branches
- `assigned_courier_id` uuid FK → user_profiles (nullable)
- `cod_amount` numeric default 0
- `currency` text default 'EGP'
- `declared_value` numeric default 0
- `shipping_charge` numeric default 0
- `total_charges` numeric default 0
- `expected_pickup_at`, `expected_delivery_at` timestamptz
- `created_by` uuid FK → user
- `created_at`, `updated_at`, `deleted_at`
- Index: `shipments_tenant_id_idx`, `shipments_tracking_idx`, `shipments_status_idx`, `shipments_customer_idx`

**shipment_packages**
- `id` uuid PK
- `shipment_id` FK → shipments
- `count` int
- `description` text
- `weight_kg` numeric
- `length_cm`, `width_cm`, `height_cm` numeric
- `volumetric_weight_kg` numeric
- `billing_weight_kg` numeric
- `package_type` text
- `fragile` boolean default false
- `returnable` boolean default false
- `handling_instructions` text

**shipment_addresses** (sender/recipient): name, phone, alternate_phone, governorate, city, area, street, building, floor, apartment, landmark, details, notes; `address_type` (sender/recipient); tenant_id denormalized.

**shipment_status_events**
- `id` uuid PK
- `shipment_id` FK → shipments
- `tenant_id` uuid FK → tenants
- `previous_status` text
- `new_status` text
- `user_id` uuid FK → user (who changed)
- `branch_id` uuid FK → branches
- `location` text
- `notes` text
- `source` text (web/mobile/api/system)
- `reference_id` uuid (process reference)
- `created_at` timestamptz
- Index: `shipment_status_events_shipment_idx`, `shipment_status_events_tenant_idx`

**shipment_documents**, **shipment_charges**, **shipment_notes**, **shipment_exceptions**, **shipment_pod** — supporting tables with `shipment_id` + `tenant_id`.

### COD & Finance (core)
**cod_collections**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `shipment_id` FK → shipments
- `courier_id` uuid FK → user_profiles
- `amount` numeric
- `method` text (cash/electronic)
- `collected_at` timestamptz
- `transaction_reference` text
- `proof` text (url)
- `status` text (collected/handed_over/reconciled/disputed)
- `created_at`

**cod_collection_items** — links collection to shipments (many-to-many with amounts).

**cod_settlements**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `customer_id` FK → customers
- `period_from`, `period_to` timestamptz
- `gross_cod` numeric
- `shipping_fee_deducted` numeric
- `net_payable` numeric
- `status` text (draft/pending/approved/paid)
- `payment_reference` text
- `paid_at` timestamptz
- `created_at`, `approved_at`, `approved_by`

**cod_settlement_items** — shipment-level breakdown within a settlement; prevents double settlement via unique constraint on `(settlement_id, shipment_id)` and application check that a shipment appears in at most one paid settlement.

**cashboxes**
- `id` uuid PK
- `tenant_id` uuid FK → tenants
- `branch_id` FK → branches
- `name` text
- `balance` numeric default 0
- `currency` text default 'EGP'
- `status` text

**cashbox_transactions**
- `id` uuid PK
- `cashbox_id` FK → cashboxes
- `tenant_id` uuid FK → tenants
- `type` text (deposit/withdrawal/transfer)
- `amount` numeric
- `reference_type` text (cod_handover/settlement/expense)
- `reference_id` uuid
- `user_id` uuid FK → user
- `created_at`

**invoices**, **invoice_items**, **payments**, **payment_allocations**, **credit_notes**, **debit_notes**, **expenses** — core accounting tables (Phase 1 skeleton; detailed double-entry in Phase 4).

**chart_of_accounts**, **journal_entries**, **journal_entry_lines** — double-entry skeleton.

## Relations (Drizzle)
- `tenants` hasMany `organizations`, `branches`, `hubs`, `departments`, `users` (via memberships), `customers`, `shipments`, `contracts`, `cod_*`, `invoices`, `audit_logs`
- `organizations` hasMany `branches`
- `customers` hasMany `shipments`, `contracts`
- `shipments` hasMany `shipment_packages`, `shipment_addresses`, `shipment_status_events`, `cod_collections`
- `branches` hasMany `shipments` (origin/destination), `manifests`, `cashboxes`

## Constraints
- No cross-tenant inserts: repository layer adds `tenant_id` from session; composite FKs enforced.
- Unique tracking number per tenant (global uniqueness also acceptable; decided per tenant for readability).
- Money stored as `numeric`; no floating-point columns for amounts.
- Soft delete via `deleted_at` on shipments/customers; hard delete prohibited on financial tables.
